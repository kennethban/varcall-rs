# Validation

The outputs of varcall-rs are required to be identical to those of the reference tools. This page defines
identity, describes the tests, and lists the known differences and limits.

## Definition of identity

Identity is assessed byte for byte:

* **BAM files:** the records, and the header apart from the `@PG` line of the tool itself.
* **VCF files:** every data line, and the header apart from the line that records the command.
* **Metrics, recalibration tables, pileup and contamination tables, and `.stats` files:** the complete files.
* **Indexes (`.bai`, `.tbi`):** either byte-identical, or returning identical answers to region queries.

The reference outputs come from bwa-mem2 2.3 (with `sort` and `index` of samtools 1.25) and GATK 4.7.0.0
(Picard 3.5.0, htsjdk 5.0.0). The bioconda build of bwa-mem2 2.3 in `environment.yml` gives records identical to those
of a build from the 2.2.1 source, from which align-rs was ported (a whole NA12878 lane of 63,787,017 records, and
the `small` and `indel` test sets). The 2.3 release still reports itself as 2.2.1 (`bwa-mem2 version` and the `@PG`
line).

The reference for a comparison is a particular set of runs and is not determined by the versions alone. Two
settings change the output of the reference tools themselves, and every comparison therefore uses the same values
for both tools:

* The records of bwa-mem2 depend on the batch size `-K`, because insert-size statistics are estimated for each
  batch. They do not depend on the number of threads.
* The records of HaplotypeCaller depend on how the genome is divided among separate GATK runs, because each run
  has its own random-number stream for downsampling and for the QD jitter. A genome called in one run, in the
  shards of WARP and in the intervals of sarek gives three VCF files from GATK that agree on nearly every call but
  differ in many records, mostly in the QD annotation alone. variant-rs is compared with each division that it is
  asked to reproduce ([how-to](how-to.md#call-a-whole-genome-in-shards-in-one-process)).

## Test tiers

| Tier | Command | Data | Time |
|---|---|---|---|
| Unit tests | `cargo test --release --workspace` | none | seconds |
| Self-contained test | `tests/selftest.sh` | a synthetic genome and reads generated by `tests/synth/simulate.py` (seeded and byte-reproducible); GATK outputs committed in `tests/truth` | ~1 min |
| Container images | `containers/test_images.sh` | the self-contained test run inside the Docker images, with additional checks on real data when `VARCALL_DATA` is set | ~5 min |
| Full harness | `tests/harness/regress.sh` | ~300 GB of public data ([tests/harness/README.md](../tests/harness/README.md)) | ~75 min |

The unit tests and the self-contained test run in continuous integration
([.github/workflows/ci.yml](../.github/workflows/ci.yml)) on every push and pull request. They run on the CPU only,
because the hosted runners of GitHub have no GPU.

### Self-contained test

The synthetic data consist of a 1.9 Mb genome and reads with the following features:

* GC drift and a repeat family;
* short tandem repeats, homopolymers, segmental duplications and N gaps;
* germline SNPs, indels, MNPs and multi-allelic sites;
* three somatic clones;
* Illumina-like quality profiles, adapters, and PCR and optical duplicates.

The test has two parts:

1. The four lanes are aligned by bwa-mem2 and by align-rs, on the GPU and on the CPU, and the records are compared.
2. variant-rs runs the command lines of GATK, once with the CPU PairHMM and once with the GPU PairHMM, and 34
   outputs per PairHMM are compared with those of GATK. The commands cover MarkDuplicates, BQSR, HaplotypeCaller
   (VCF and GVCF), GenotypeGVCFs (from a GVCF and through a GenomicsDB workspace), Mutect2 and its filters, a panel
   of normals, VQSR (VariantRecalibrator, ApplyVQSR) and VariantFiltration / MakeSitesOnlyVcf.

The GATK outputs are committed in `tests/truth`. They were produced with the release jar of GATK
(`gatk-package-4.7.0.0-local.jar` from `gatk-4.7.0.0.zip` on GitHub, SHA-256 `882e1807…3861365`), and
`tests/make_truth.sh` regenerates them.

### Full harness

`regress.sh` runs 50 checks in about 75 minutes. To fit within this time, it uses subsets and slices of the data,
variants of the arguments, and edge cases. Each comparison of a complete genome or exome requires hours of GATK
run time, and these comparisons were therefore run separately, with the scripts in the harness folders. The
following table lists both kinds of comparison.

| Tool | Data | Result |

| HaplotypeCaller | NA12878 30x WGS (BAM and CRAM; 23 and 97 shards); HG002 35x WGS, HG002 PCR+ 30x WGS, HG002 exome | VCF and GVCF identical (e.g. NA12878: 5,064,948 VCF and 461,802,035 GVCF lines; HG002 PCR+: 583,697,036 GVCF lines) |

Because the outputs are identical, the accuracy of variant-rs equals that of GATK. On HG002 against the GIAB v4.2.1
benchmark (chr1 to chr22), both give precision 0.9887, recall 0.9923 and F-measure 0.9905.

## Adversarial review

The first crash on real data occurred on an input that the comparisons of final outputs had not reached. The code
was then reviewed for defects of the same class. Eight independent reviewers (AI agents) were each assigned one
area, four in align-rs and four in variant-rs. Each compared the code with the source of the reference tools
(bwa-mem2, GATK, Picard, htsjdk) and reported concrete inputs for which the outputs would diverge. A separate
reviewer then attempted to refute each finding.

Every fix was accompanied by a regression test that failed before the fix, and these tests are now part of the
harness.

| | |
|---|---|
| Findings | 45: 36 confirmed, 3 unverified, 6 refuted |
| Fixed | 37 of the 39 confirmed or unverified, plus 1 refuted finding |
| Not fixed | 2, listed under [Known differences and limits](#known-differences-and-limits) |

The findings fell into four categories:

* **Crashes on rare inputs:**
  * reads of 725 bp or more;
  * an empty mate;
  * references under ~500 Mb with `--gpu`;
  * a BAM bucket over 4 GiB;
  * reads spanning over 131 kb (HaplotypeCaller) or 4.8 kb (Mutect2);
  * a short, very deep contig in the shard planner;
  * an empty input in GatherBamFiles;
  * Picard list-file inputs.
* **Silent wrong output:**
  * an assembly failure skipped the region where GATK fails the run;
  * MarkDuplicates and ApplyBQSR on CRAM dropped unplaced reads;
  * quality scores ≥ 94 indexed the wrong table cells;
  * the BAM `bin` field was copied instead of recomputed;
  * `.bgz` outputs were written as plain text;
  * a failed GPU allocation aborted the run instead of falling back to the CPU.
* **Edge-case divergence from the reference:**
  * malformed FASTQ, now read exactly as `kseq_read` does;
  * `.alt` parsing;
  * NaN ordering (`Double.compare`);
  * case-insensitive allele matching;
  * `<NON_REF>` in FilterMutectCalls;
  * contig order without `-L`;
  * htsjdk's QUAL round trip;
  * H tags;
  * records at POS 0;
  * Java's signed bytes for qualities ≥ 128;
  * duplicate sample tables.
* **Pipeline robustness:** `pipefail` on the bwa-mem2 branch; duplicate (sample, lane) rows.

## Known differences and limits

* **AVX-512 mate rescue of bwa-mem2** (`kswv`). This kernel counts rows in 16-bit integers, which overflow for
  rescue windows of 32 kb or more. align-rs gives the result of the scalar `ksw_align2` of bwa, which bwa-mem2 also
  uses on CPUs without AVX-512. Windows of this size require very large insert sizes, and none occurred in the test
  data.
* **MarkDuplicates.** Reads can be paired differently from Picard when the same combination of read group and read
  name occurs in two pairs whose reads fall in different 2 Mb chunks. Such input is malformed, and the result of
  Picard for it also depends on the order of the records.
* **The same read in two HaplotypeCaller inputs.** This input is refused, because GATK collapses identical reads in
  some of its hash-keyed maps and not in others.
* **Unsupported inputs and arguments.** Any input or argument outside those listed in [reference.md](reference.md)
  is refused, or is passed to GATK when `GATK_FALLBACK` is set. In no case is a different result produced silently.
* **Hardware tested.** The full harness has been run on one GPU model (RTX 5070 Ti, sm_120) and one CPU (16-core
  Zen 5, with AVX-512). On a server with L40S GPUs (sm_89) and EPYC 9654 CPUs, the pipeline tests, NA12878 30x from
  FASTQ files on 1 and 6 GPUs, and the SEQC2 exome pair gave the same outputs as on the workstation. The CPU PairHMM
  without AVX-512 is checked by the self-contained test, with `VARIANT_RS_NO_AVX512=1` and on continuous-integration
  runners that lack AVX-512.
